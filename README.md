# Скальпинг-бот Bybit USDT perpetual

Откат по тренду на linear BTCUSDT. Один процесс держит не больше одной позиции.
Боевой счёт сам не включается. Стартовые цифры в `config/default.yaml` — гипотезы, не оптимизированный набор.

Проверено в этой среде на Python 3.10.21. Код рассчитан на Python 3.10 и 3.11+.
Подключение к бирже: официальный SDK [pybit 5.17.0](https://github.com/bybit-exchange/pybit) (`HTTP`, приватный WebSocket).
Публичный стакан читается сырым потоком V5: в pybit 5.17.0 callback стакана уже склеен в snapshot, и дыра `u` в нём не видна.

[okx/go-wallet-sdk](https://github.com/okx/go-wallet-sdk) — кошельки и подпись блокчейн-транзакций. В зависимости бота он не входит: для фьючерсов Bybit не нужны сид-фразы.

## Режимы

| Команда | Что делает |
|---|---|
| `offline` | Свечи из `data/btcusdt_1m_sample.csv` без ключей. High/low не считаются исполнением. |
| `paper` | Публичный рынок Bybit, заявки только в симуляторе. Ключи не нужны. |
| `testnet` | `config/testnet.yaml`, ключи testnet, ордера на testnet. |
| `live` | Только если дополнительно `LIVE_CONFIRM=YES`. |

ETHUSDT не торгуется, пока в конфиге не стоит `eth_enabled: true` после отдельной проверки.

## Установка (Windows PowerShell)

```powershell
cd bybit-scalper
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
$env:PYTHONPATH = "src"
```

Если `py -3.11` нет, поставьте Python 3.11 с python.org или используйте уже установленный 3.10: `py -3.10 -m venv .venv`.

Проверка без сети и без ключей:

```powershell
python -m pytest -q
python -m bybit_scalper offline --config config/default.yaml
```

Отчёт пишется в консоль и в `data/last_report.txt`. Там два хронологических куска 70/30 и отдельная проверка контура. Параметры на проверочном куске не подгоняются. Цифры предварительные.

## Paper

```powershell
$env:MODE = "paper"
python -m bybit_scalper paper --config config/default.yaml
```

Нужен доступ к `stream.bybit.com` и `api.bybit.com`. Если хост их режет, процесс завершится с текстом ошибки и не подменит рынок случайными сделками.
Исполнение paper — только лента `publicTrade` и только если `trade_flow_enabled: true`. По умолчанию лента выключена: сигналы считаются, лимитка не считается исполненной от фитиля свечи.

Остановка: `Ctrl+C`. Рабочий вход снимается. Открытая позиция остаётся только вместе с уже подтверждённым стопом.

Повторный запуск читает `data/state.db` и не ставит вторую входную заявку поверх сохранённой позиции.

## Testnet

В `.env` (файл не коммитить):

```text
MODE=testnet
BYBIT_API_KEY=ключ_из_testnet
BYBIT_API_SECRET=секрет_из_testnet
```

```powershell
$env:MODE = "testnet"
$env:BYBIT_API_KEY = "ключ_из_testnet"
$env:BYBIT_API_SECRET = "секрет_из_testnet"
python -m bybit_scalper testnet --config config/testnet.yaml
```

Ключи только от testnet. Доходность testnet не доказывает результат на основном рынке.
Комиссии берутся из `get_fee_rates` и подменяют 0.020% / 0.055% из конфига.
Плечо выше 2× или hedge mode (`positionIdx` 1 или 2) останавливают запуск. Бот не вызывает `set_leverage`, `switch_margin_mode` и `switch_position_mode`, особенно если на счёте есть чужие позиции.

## Боевой запуск

Автоматически не стартует.

```powershell
$env:MODE = "live"
$env:BYBIT_API_KEY = "боевой_ключ"
$env:BYBIT_API_SECRET = "боевой_секрет"
$env:LIVE_CONFIRM = "YES"
python -m bybit_scalper live --config config/default.yaml
```

Без `LIVE_CONFIRM=YES` код выхода 2.

Остановка снова `Ctrl+C`. Состояние в `data/state.db` (для testnet — `data/state-testnet.db`).

```powershell
python -m bybit_scalper report --config config/default.yaml
```

## Правила входа и выхода

Направление только по закрытым 5m: EMA20 и EMA50, обе растут или обе падают (`rise_lookback_5m` закрытых пятиминуток), цена относительно дневного VWAP с 00:00 UTC.

Вход по закрытой 1m: откат касается полосы EMA20 ± ATR, закрытие возвращается по сторону тренда и пробивает high/low предыдущей 1m. Локальный экстремум — бар ниже или выше обоих соседей, правый сосед уже закрыт. Более высокий минимум (для long) — последний подтверждённый минимум строго выше предыдущего. Будущие свечи не читаются.

Вход: `Limit` + `PostOnly`, ожидание `entry_timeout_sec` (3). Остаток отменяется. Исполнение, пришедшее вместе с отменой, учитывается. В рынок просроченный вход не переписывается.
Частичное исполнение сразу становится позицией. Защита: `set_trading_stop`, `tpslMode=Full`, рыночные SL/TP. Если стоп не подтверждается, новые входы блокируются и позиция закрывается reduce-only market.
Цель считается так, чтобы чистая прибыль была не меньше `reward_multiple` (1.5) планового убытка после taker-комиссии, проскальзывания и funding, если 5 минут удержания пересекают время funding. Ближний противоположный экстремум, который не вмещает эту цель, отменяет сделку.
Держать дольше `max_hold_sec` (300) нельзя.

Риск сделки `risk_pct` (0.1% капитала) вместе с расходами. Дневной стоп 1% от капитала на начало суток UTC, включая открытый результат; он пишется в SQLite и переживает перезапуск. Четыре убытка подряд — пауза 30 минут. Плечо не выше 2×. Усреднение и мартингейл выключены. Объём в `Decimal`, вниз до шага цены и количества. Если минимальный ордер больше допустимого риска, сделки нет.

`orderLinkId` уникален. `execId` не проводится дважды. Ответ HTTP «принято» — это не сделка. Таймаут place переводит заявку в неизвестное состояние и запрещает новый вход, пока сверка не найдёт её. Переподключение SDK само по себе состояние не чинит: после разрыва идёт сверка ордеров, исполнений и позиции. Переполнение очереди или устаревшие свеча/стакан блокируют новые входы.

## Что считает отчёт

Чистый PnL, ожидание на сделку, profit factor, максимальную просадку, число сделок, долю исполнений, комиссии и оценку проскальзывания.
В offline доля исполнений на свечах равна нулю: трёхсекундный PostOnly нельзя честно заполнить минутным баром. Блок «проверка контура» гоняет одну синтетическую ленту и не является рыночной доходностью.

## Тесты

`python -m pytest -q` не ходит на биржу и не требует ключей. Покрыты lookahead, риск с округлением и комиссиями, частичное исполнение, гонка отмены и сделки, таймаут после принятия заявки, повтор `execId`, обрыв и сверка, перезапуск с позицией, отказ стопа, дневной лимит в SQLite.
