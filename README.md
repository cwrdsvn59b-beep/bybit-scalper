# Скальпинг-бот Bybit USDT perpetual

Откат по тренду на linear BTCUSDT. Один процесс держит не больше одной позиции.
Боевой счёт сам не включается. Стартовые цифры в `config/default.yaml` — гипотезы, не оптимизированный набор.

Исходная версия заявляла Python 3.10.21. Предыдущий аудит описывал прогон на Python 3.12. Этот проход выполнен на Python 3.10.21; Windows отдельно не проверен. Код рассчитан на Python 3.10+.
Подключение к бирже: официальный SDK [pybit 5.17.0](https://github.com/bybit-exchange/pybit) (`HTTP`, приватный WebSocket).
Публичный стакан читается сырым потоком V5: обновления применяются как snapshot/delta. `u` не обязан возрастать на единицу. После потери соединения или переполнения очереди нужен новый snapshot.

[okx/go-wallet-sdk](https://github.com/okx/go-wallet-sdk) — кошельки и подпись блокчейн-транзакций. В зависимости бота он не входит: для фьючерсов Bybit не нужны сид-фразы.

## Режимы

| Команда | Что делает |
|---|---|
| `offline` | Свечи из `data/btcusdt_1m_sample.csv` без ключей. High/low не считаются исполнением. |
| `paper` | Публичный рынок Bybit, заявки только в симуляторе. Ключи не нужны. База `data/state.db`. |
| `testnet` | `config/testnet.yaml`, ключи testnet, база `data/state-testnet.db`. |
| `live` | `config/live.yaml` и `LIVE_CONFIRM=YES`. База `data/state-live.db`. Это не допуск к реальным деньгам. |
| `collect` | Публичные свечи и сделки. Ошибка сети завершает команду, файл-заглушка не пишется. |
| `replay` | Только сохранённая лента. Если её нет, статистика не выдумывается. |

ETHUSDT не торгуется, пока в конфиге не стоит `eth_enabled: true` после отдельной проверки.

## Установка (Windows PowerShell)

```powershell
cd bybit-scalper
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -e .
Copy-Item .env.example .env
```

Если `py -3.11` нет, поставьте Python 3.11 с python.org или используйте уже установленный 3.10: `py -3.10 -m venv .venv`.

Проверка без сети и без ключей:

```powershell
python -m pytest -q
python -m bybit_scalper offline --config config/default.yaml
```

**Статус: исследовательская версия для offline/paper и последующей интеграционной проверки. Готовность к реальным деньгам не подтверждена. См. [AUDIT.md](AUDIT.md).**

Отчёт пишется в консоль и в `data/last_report.txt`. Там два хронологических куска 70/30 и отдельная проверка контура. Параметры на проверочном куске не подгоняются. Цифры предварительные.

## Paper

```powershell
$env:MODE = "paper"
python -m bybit_scalper paper --config config/default.yaml
```

Нужен доступ к `stream.bybit.com` и `api.bybit.com`. Если хост их режет, процесс завершится с текстом ошибки и не подменит рынок случайными сделками.
Исполнение paper использует `publicTrade` всегда, включая сторону агрессора. `trade_flow_enabled` управляет только дополнительным фильтром сигнала: за последние 5 секунд объём агрессивных покупок должен превышать продажи для long (для short наоборот). По умолчанию фильтр выключен; симуляция исполнения при этом работает. Очередь перед лимитом пока модельная и требует калибровки.

Остановка: `Ctrl+C`. Рабочий вход снимается. Открытая позиция остаётся только вместе с уже подтверждённым стопом.

Повторный запуск paper читает `data/state.db`. Testnet читает `data/state-testnet.db`, live — только `data/state-live.db`. Live с базой `data/state.db` не запускается. База привязана к режиму, инструменту и отпечатку аккаунта. Старую непустую базу без идентификатора автоматически не переносим.

Файловая блокировка запрещает второй процесс **на том же файле базы**. Две разные базы или два компьютера на одном аккаунте она не останавливает. При старте testnet/live бот прерывается, если видит чужую входную заявку, но это не распределённый замок. Поддерживается один экземпляр на один аккаунт.

## Testnet

В `.env` (файл не коммитить):

```text
MODE=testnet
BYBIT_API_KEY=ключ_из_testnet
BYBIT_API_SECRET=секрет_из_testnet
```

```powershell
$env:MODE = "testnet"
$env:BYBIT_API_KEY = "ключ_из_testnet"
$env:BYBIT_API_SECRET = "секрет_из_testnet"
python -m bybit_scalper testnet --config config/testnet.yaml
```

Ключи только от testnet. Доходность testnet не доказывает результат на основном рынке.
Комиссии берутся из `get_fee_rates` и подменяют 0.020% / 0.055% из конфига.
Плечо выше 2× или hedge mode (`positionIdx` 1 или 2) останавливают запуск. Бот не вызывает `set_leverage`, `switch_margin_mode` и `switch_position_mode`.
`PORTFOLIO_MARGIN` и неизвестный `tradeMode` не меняются: новые входы блокируются, уже открытая позиция остаётся под сверкой.

## Боевой запуск

Автоматически не стартует. Наличие команды и LIVE_CONFIRM не означает готовности к торговле: сначала устраните ограничения из AUDIT.md и пройдите интеграционную проверку. Бот предполагает отдельный субсчёт, выделенный целиком под него. Проверяйте, что второй экземпляр не использует тот же аккаунт с другой базой или другой машины.

```powershell
$env:MODE = "live"
$env:BYBIT_API_KEY = "боевой_ключ"
$env:BYBIT_API_SECRET = "боевой_секрет"
$env:LIVE_CONFIRM = "YES"
python -m bybit_scalper live --config config/live.yaml
```

Без `LIVE_CONFIRM=YES` код выхода 2. `LIVE_CONFIRM` только не даёт запуститься случайно.

Остановка: `Ctrl+C`. Состояние paper — `data/state.db`, testnet — `data/state-testnet.db`, live — `data/state-live.db`.

```powershell
python -m bybit_scalper report --config config/default.yaml
```

## Капитал, маржа и funding

`allocated_capital` — потолок риска. Весь `totalEquity` UNIFIED сам бюджетом не становится. Дневной порог считается как 1% выделенного капитала, включая открытый результат, уплаченные комиссии и фактический funding этих суток UTC. Переводы `TRANSFER_IN` / `TRANSFER_OUT` в торговый PnL не входят.

Новый вход ещё требует подтверждённую доступную маржу, плечо не выше 2× и понятный режим cross/isolated. К номиналу добавляются две taker-комиссии, `slippage_bps` и `adverse_reserve_bps`. Если проверка не удалась, заявки нет.

Funding берётся из исполнений `execType=Funding` и из журнала `SETTLEMENT`. Одинаковый `execId` / `tradeId` пишется один раз. Пока журнал не подтверждён, сделка, которая может пересечь funding, не ставится. В paper и на бирже неизвестное `nextFundingTime` тоже блокирует вход. У offline биржевых часов нет, поэтому там этот запрет не применяется; отчёт это прямо говорит.

## Сбор и воспроизведение

```powershell
python -m bybit_scalper collect --config config/default.yaml
python -m bybit_scalper replay --config config/default.yaml
```

`collect` ходит только в публичные kline и recent-trade. Сеть оборвалась — процесс выходит с текстом ошибки и не подставляет синтетику. `replay` без файлов в `data/replay` сообщает, что ленты нет, и не печатает выдуманную доходность. Касание high/low по-прежнему не является исполнением.

Интеграционный тест Testnet выключен, пока нет `$env:BYBIT_INTEGRATION = "1"`. Ключи в репозиторий не класть.

## Правила входа и выхода

Направление только по закрытым 5m: EMA20 и EMA50, обе растут или обе падают (`rise_lookback_5m` закрытых пятиминуток), цена относительно дневного VWAP с 00:00 UTC.

Вход по закрытой 1m: откат касается полосы EMA20 ± ATR, закрытие возвращается по сторону тренда и пробивает high/low предыдущей 1m. Локальный экстремум — бар ниже или выше обоих соседей, правый сосед уже закрыт. Более высокий минимум (для long) — последний подтверждённый минимум строго выше предыдущего. Будущие свечи не читаются.

Вход: `Limit` + `PostOnly`, ожидание `entry_timeout_sec` (3). Остаток отменяется. Исполнение, пришедшее вместе с отменой, учитывается. В рынок просроченный вход не переписывается.
Частичное исполнение сразу становится позицией и заново ставит `set_trading_stop` на весь объём. Поздний входной fill, пока выход ещё не подтверждён, не создаёт второе закрытие: вход блокируется до ручной сверки.
Цель считается так, чтобы чистая прибыль была не меньше `reward_multiple` (1.5) планового убытка после taker-комиссии, проскальзывания и funding, если 5 минут удержания пересекают время funding. Ближний противоположный экстремум, который не вмещает эту цель, отменяет сделку.
Держать дольше `max_hold_sec` (300) нельзя.

Риск сделки `risk_pct` (0.1% выделенного капитала) вместе с расходами. Дневной стоп 1% выделенного капитала; он пишется в SQLite и не снимается переподключением. Четыре убытка подряд — пауза 30 минут. Плечо не выше 2×. Усреднение и мартингейл выключены. Объём в `Decimal`, вниз до шага цены и количества. Если минимальный ордер больше допустимого риска, сделки нет. Проскальзывание может сделать фактический убыток больше планового.

`orderLinkId` уникален. `execId` не проводится дважды. Ответ HTTP «принято» — это не сделка. Сделка ленты раньше `opened_ms` заявки не исполняет paper-лимит. Закрытие сохраняет свой orderLinkId до сетевого запроса; все его исполнения учитываются, неизвестный результат не приводит к слепой повторной отправке. Отмена становится окончательной только после подтверждения конечного статуса. Исполнение и его учёт записываются одной транзакцией SQLite. Таймаут place переводит заявку в неизвестное состояние и запрещает новый вход, пока сверка не найдёт её. Переподключение SDK само по себе состояние не чинит: после разрыва идёт сверка ордеров, исполнений и позиции. Публичная очередь может выбросить котировку и запросить новый snapshot. Приватные исполнения идут отдельной очередью и котировками не вытесняются; если переполняется уже она, новые входы блокируются.

## Что считает отчёт

Чистый PnL, ожидание на сделку, profit factor, максимальную просадку, число сделок, долю исполнений, комиссии и оценку проскальзывания.
В offline доля исполнений на свечах равна нулю: трёхсекундный PostOnly нельзя честно заполнить минутным баром. Блок «проверка контура» гоняет одну синтетическую ленту и не является рыночной доходностью.

## Тесты

`python -m pytest -q` не ходит на биржу и не требует ключей. Покрыты lookahead, риск с округлением и комиссиями, частичное исполнение, гонка отмены и сделки, таймаут после принятия заявки, повтор `execId`, обрыв и сверка, перезапуск с позицией, отказ стопа, дневной лимит в SQLite, funding без двойного учёта, перевод средств, граница UTC, нулевая маржа, лента до открытия заявки, повторный стоп, поздний fill во время выхода и отдельная приватная очередь. Тест Testnet включён только при `BYBIT_INTEGRATION=1`.
