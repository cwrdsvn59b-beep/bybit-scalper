# Дополнительная проверка PR №1, 16 октября 2026

Проверен `352389b029f3cf1988a760b9511ed0a1ad599276`, ветка `spec-hardening`.
Исходный результат на Python 3.10 в этой среде был 70 passed, 1 skipped.
Ниже — исправления по найденным ошибкам. Ордера не отправляются.

## Исправления

1. `SETTLEMENT.cashFlow` заменён на `SETTLEMENT.funding`. По V5 funding положителен
   при получении и отрицателен при списании. Missing/NaN funding не превращается в ноль.
2. Transaction-log стал единственным источником денежного funding. Совпадение
   execId/tradeId между разными API не считается гарантированным протоколом.
3. Явные временные окна, пагинация и ограничения окна V5. Записи SETTLEMENT и переводов
   запрашиваются отдельно по типу, чтобы не сканировать тысячи торговых событий.
   Неудача любой страницы сохраняет предыдущий снимок и снимает подтверждение журнала.
4. Полностью полученный funding-интервал заменяется одной транзакцией. Это исправляет
   старые нули и дубли в покрытом интервале, не обнуляя сделки и дневные ограничения.
5. Неизвестный режим маржи больше не подтверждается через tradeMode=0. Для текущего
   читателя поддержан REGULAR_MARGIN; isolated/portfolio блокируют входы. Для isolated
   account-wide totalEquity/totalAvailableBalance неприменимы. Смена режима не производится.
6. Маржа с резервом должна помещаться также в allocated_capital, а не только в средства
   всего аккаунта. Перед кандидатом на вход выполняется свежая проверка аккаунта;
   если за время HTTP-проверки устарел стакан, вход пропускается.
7. Прошедшее nextFundingTime не разрешает входы: требуется обновлённое будущее время.
8. Общий локальный замок по аутентифицированному UID и окружению применяется до
   восстановления торгового состояния. Он не зависит от пути базы и API-ключа.
   Другие машины, пользователи ОС и разные BYBIT_LOCK_DIR остаются вне этой защиты.
9. Команда report читает выбранный режим через readonly SQLite, а не случайный
   offline-кэш. Funding и сумма с торговым PnL показаны отдельно. Метрики закрытых
   сделок не выдаются за полную кривую капитала с funding и открытым результатом.
10. Убран расчёт replay на искусственном bid/ask из минутного close. Загруженные свечи
    и последние сделки без синхронного стакана/funding недостаточны для такого отчёта.

`compileall` и `git diff --check` завершились без вывода. Пропущенный тест — публичное время Testnet и только при `BYBIT_INTEGRATION=1`.

Старые моки SETTLEMENT обновлены до фактического V5: funding=-1.25, cashFlow=0.
Пропущенный тест делает только публичный запрос времени Testnet. Он не проверяет
авторизованные заявки, стопы, частичные исполнения или восстановление на бирже.
Ключей нет; авторизованный Testnet и live не запускались. Windows не проверен.

## Остающиеся ограничения

- Нужны полноценные авторизованные Testnet-сценарии и независимые рыночные данные.
- Полноценный сбор синхронного стакана/funding и событийный replay не реализованы;
  collect сохраняет лишь свечи и recent-trades. Положительное ожидание не доказано.
- Funding в отчёте выделен отдельно; profit factor, expectancy и drawdown закрытых
  сделок не включают распределение funding. Полная кривая капитала ещё не построена.
- Живые доступность transaction-log, задержка появления SETTLEMENT и работа маржи
  конкретного аккаунта не проверялись. Локальный замок не является распределённым.
- Isolated и portfolio не торгуются этой версией. Передача общего аккаунта боту
  не поддерживается. Выделенный бюджет не ограничивает саму биржевую cross-ликвидацию.

Не сливать и не считать версию готовой к реальным деньгам только по числу тестов.
